# 사용 가이드

> [문서 안내](README.md) · 사용자 가이드

이 가이드는 ACL Research Radar를 실행하고 공고를 수집·검토하는 절차를 설명합니다. GPT 모델과 API Key는 [GPT 설정](GPT_API.md), 오류 진단은 [문제 해결](TROUBLESHOOTING.md)을 참고하세요.

## 시작 전 준비

- Python 3.10 이상과 브라우저
- 프로젝트 소스
- PDF 추출용 의존성: `python -m pip install -r requirements-optional.txt`

기본 데이터 폴더는 `~/ACLBriefingData`입니다. 다른 위치를 사용하려면 `ACL_DATA_DIR`를 설정합니다.

## 1. 대시보드 실행

```bash
python run.py serve
```

Windows는 `start_windows.bat`, macOS/Linux는 `python3 run.py serve`로 실행할 수 있습니다. 브라우저에서 `http://127.0.0.1:8765`를 열고 화면 하단 버전이 **0.7.1**인지 확인하세요.

대시보드를 사용하는 동안 서버 실행 창을 열어 둡니다. 종료할 때는 Ctrl+C를 누릅니다. 원문·버전·피드백·경로 선택은 데이터 폴더에 보관됩니다.

## 2. 수집 경로 선택과 수집

1. **수집 경로**에서 확인할 기관을 선택합니다. 전체 선택·해제를 사용할 수 있습니다.
2. **공고 수집**을 실행합니다.
3. 기관별 상태와 마감·제목·기간 확인 건수를 확인합니다.
4. **공고 검토함**에서 결과를 엽니다.

선택한 기관에 공식 재게시 경로가 등록돼 있으면 자동으로 함께 확인합니다. 공유 경로는 한 번만 확인합니다.

| 선택 기관 | 자동 포함 경로 |
|---|---|
| IITP·NRF·NTIS | IRIS·KOITA |
| ETRI | KOITA |
| 미래도전·신속시범 | 방위사업청 |
| KRIT PMS | DTiMS |

직접 선택한 경로와 자동 포함 경로를 화면에서 구분하며, 원기관과 재게시 출처의 결과를 따로 기록합니다. 재게시 공고의 변경·마감 정보는 원문과 함께 확인하세요.

## 3. 결과 확인

| 표시 | 의미 | 다음 작업 |
|---|---|---|
| 추천 | 연구 내용·자격·마감·핵심 자료 확인을 통과 | 인용문과 원문을 대조하고 신청 여부 결정 |
| 관련 후보 | 연구 관련성은 있으나 자격·자료 등 추가 확인 필요 | 상세 화면의 확인 필요 항목 보완 |
| 검토 대기 | 자료 부족, 처리 실패 또는 적합도 기준 미달 | 보류 이유와 수집 진단 확인 |
| 제목 미선별 | 제목에서 통신 관련 표현을 확인하지 못함 | 필요한 경우 원문을 직접 확보해 검토 |

기본 화면은 **추천·관련 후보**를 함께 보여줍니다. 관련 후보는 추천 건수에서 제외됩니다. 브리핑은 추천 최대 20건과 관련 후보 최대 10건을 표시합니다.

공고 상세에서 판정 문장, 출처 파일과 연결 실적을 확인하세요. 판단을 기록할 때는 관련 여부, 이유, 기준 조정용·평가용 구분을 선택합니다.

## 4. 직접 확보한 자료 가져오기

새 공고는 **브라우저 자료 가져오기**, 기존 공고는 상세 화면의 **직접 받은 자료로 보완**을 사용합니다.

1. 복사한 본문·저장 HTML·첨부 파일을 준비합니다.
2. 해당 공고의 자료를 입력하거나 파일을 추가합니다.
3. 서로 다른 RFP는 별도 공고로 입력합니다.
4. 미확보 필수 자료를 모두 제공했을 때만 해당 체크박스를 선택합니다.
5. 다시 계산한 결과와 원문 인용을 확인합니다.

본문을 입력하면 이전 본문을 교체하고, 파일만 추가하면 기존 본문에 덧붙입니다. 파일명·해시·확보 시각·원 URL과 원문 버전을 보존합니다. 자동 수집은 수동 보완 자료를 유지하며, 공식 원문 변경을 발견하면 다시 대조하도록 보류합니다.

| 형식 | 처리 |
|---|---|
| TXT·MD·HTML | 텍스트 추출 |
| PDF | pypdf로 텍스트 추출. Windows는 `setup_optional_windows.bat`로 설치 가능 |
| HWP 5·HWPX·DOCX | 문서 텍스트 추출 |
| ZIP | 내부 지원 문서 추출. 여러 과제는 분리 입력 권장 |
| 이미지·암호화 파일·구형 DOC·손상 문서 | 직접 확인·변환 필요 |

파일은 하나씩 임시 파일로 전송합니다. 용량·파일 수·PDF 쪽수·본문 길이에 고정 상한을 두지 않으며 실제 처리량은 메모리·디스크·파일 구조에 따라 달라집니다. 압축 해제 비율과 16단계 이상 중첩 보호를 적용합니다. [GPT 전송 한도](GPT_API.md#호출-한도와-오류-처리)는 별도입니다.

## 업데이트

1. 기존 서버를 Ctrl+C로 종료합니다.
2. 새 소스를 별도 폴더에 내려받습니다.
3. 기존과 같은 데이터 폴더로 실행합니다. `ACL_DATA_DIR`를 사용했다면 같은 값을 유지합니다.
4. 화면의 버전을 확인하고 **공고 다시 분석 → 공고 수집**을 실행합니다.

재분석은 저장된 본문을 검토하고, 수집은 필요한 상세·첨부를 새로 가져옵니다. 원문·프로필·검토 방식이 바뀐 자료에는 재분석 안내가 표시됩니다.

## 수집 순서와 재개

**접수기간 확인 → 제목 선별 → 기간 내 후보의 본문·첨부 검토 → 결과 정렬** 순서로 처리합니다.

- 기간이 불명확한 통신 후보는 상세 HTML에서 다시 확인합니다. 계속 불명확하면 첨부 분석을 보류합니다.
- 마감 당일 종료 시각이 불명확하거나 첨부에만 마감일이 있으면 직접 확인이 필요합니다.
- 상세 본문의 마감일을 목록보다 우선합니다. 날짜는 접수 관련 항목에서 찾습니다.
- 기관별 목록 한 쪽과 대기 상세 묶음을 처리한 뒤 다음 기관으로 이동합니다.
- 페이지·공고 총량에 고정 상한을 두지 않고 발견한 페이지 링크를 따라갑니다.
- 반복 목록과 미지원 동적 페이지는 진단에 기록합니다.
- **수집 중지**로 멈추면 다음 실행에서 이어갑니다. 성공한 상세는 24시간 동안 재요청을 생략하고, 실패한 상세는 실행당 한 번 시도합니다.
- 마감 공고는 목록 제목·접수정보가 유지되는 동안 재방문하지 않습니다. 제목·기간·상태가 바뀌면 다시 확인합니다. 목록에 없는 원문 내부 변경은 직접 확인해야 합니다.

## 요청 설정

기본은 직접 HTTP 요청입니다. `ACL_RESPECT_ROBOTS=1`을 설정하면 robots.txt 확인을 켭니다. 목록과 첨부에 같은 데스크톱 브라우저 형식의 User-Agent를 사용하며 `ACL_USER_AGENT`로 변경할 수 있습니다. 실제 설정은 진단에 기록합니다.

401/403/429, 로그인·CAPTCHA 화면, 미지원 동적 목록은 오류·확인 필요로 표시합니다. TLS 인증서 확인, 공개 주소 검사, 요청 간격과 제한된 오류 재시도를 적용합니다. 과거 robots 제한 기록은 새 요청 결과로 갱신됩니다.

같은 수집 방식이 CLI와 `daily_run.py`에도 적용됩니다. ChatGPT 예약 작업은 별도로 관리합니다.
