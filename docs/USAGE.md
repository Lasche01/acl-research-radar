# 사용 방법

현재 버전은 v0.7.1입니다. Python 3.10 이상과 브라우저가 필요합니다. 기본 규칙 모드로 실행하거나 [GPT 모드](GPT_API.md)를 선택할 수 있습니다.

## 설치와 업데이트

처음 실행한다면 프로젝트 폴더에서 다음 명령을 사용하세요.

```bash
# PDF 추출용 선택 의존성
python -m pip install -r requirements-optional.txt
python run.py serve
```

Windows에서는 `start_windows.bat`, macOS/Linux에서는 `python3 run.py serve`로 실행합니다.

업데이트할 때는 기존 창에서 Ctrl+C로 서버를 종료하고 새 소스를 별도 폴더에 받으세요. 새 폴더에서 실행한 뒤 화면 하단 버전이 **0.7.1**인지 확인하고 **공고 다시 분석 → 공고 수집** 순서로 진행합니다. 재분석은 저장된 본문을 검토하고, 수집은 필요한 상세·첨부를 새로 가져옵니다.

기본 데이터 폴더는 `~/ACLBriefingData`입니다. 원문·변경 이력·피드백·경로 선택이 이 폴더에 저장됩니다. `ACL_DATA_DIR`를 지정했다면 업데이트 후에도 같은 값을 사용하세요. 원문·프로필·검토 방식이 바뀐 자료에는 재분석 안내가 표시됩니다.

## 공고 수집 순서

1. **접수기간 확인**: 목록의 접수기간·마감일·상태를 확인합니다. 마감 공고와 접수 시작 전 공고는 상세 요청을 생략합니다. 날짜는 접수 관련 항목에서 찾습니다.
2. **제목 선별**: 통신·전파·무선·네트워크·파형·빔·채널·MIMO·CSI·AFDM 등의 표현으로 후보를 고릅니다. 제목이 불명확하면 **제목 미선별**에 보관하고, 행정 안내나 명백한 타 산업 문서는 제외합니다.
3. **기간 재확인**: 기간이 불명확한 통신 후보는 상세 HTML을 읽습니다. 여전히 확인할 수 없으면 **기간 미확인**으로 남깁니다. 첨부에만 마감일이 있거나 마감 당일 종료 시각이 없으면 직접 확인이 필요합니다.
4. **본문·첨부 검토**: 기간 내 후보의 공고문과 RFP에서 연구 목표, 연구실 실적과의 관련성, 대학 자격, 세부 과제를 확인합니다. 상세 본문의 마감일을 목록보다 우선합니다.
5. **결과 정렬**: 조건을 통과한 공고를 추천하고 적합도 순으로 보여줍니다. 관련성은 있지만 자격·자료 확인이 필요한 공고는 관련 후보로 남깁니다.

기관별로 목록 한 쪽과 대기 중인 상세 묶음을 처리한 뒤 다음 기관으로 이동합니다. 페이지·공고 총량에 고정 상한을 두지 않고 발견한 페이지 링크를 따라갑니다. 반복되는 목록이나 미지원 동적 페이지는 진단에 기록합니다. **수집 중지**로 멈추면 다음 실행에서 이어갈 수 있습니다.

성공한 상세는 24시간 동안 재요청을 생략하고, 실패한 상세는 실행당 한 번 시도합니다. 마감 공고는 목록 제목·접수정보가 그대로인 동안 재방문하지 않습니다. 목록에서 제목이나 기간·상태가 바뀌면 다시 확인합니다. 목록에 드러나지 않는 원문 내부의 접수 재개는 직접 확인해야 합니다.

수집 경로 화면에는 마감·시작 전·제목 보류·기간 미확인·상세 분석·기확인 건수를 표시합니다. 기존에 저장한 공고와 원문 이력은 보존합니다.

## 추천이 0건일 때

**제목 미선별 → 기간 확인 대기 → 상세 심사 기록** 순서로 진행 단계를 확인하세요. 제목에서 보류한 자료는 **제목 미선별** 또는 **전체 수집 자료**에서 볼 수 있습니다.

**공고 다시 분석 → 공고 수집**을 실행한 뒤에도 0건이면 **수집 진단 내려받기**로 본문 길이, 첨부 상태와 공고별 보류 이유를 확인하세요. 링크 추출 실패, 기간 미확인, 핵심 자료 부족, 자격 미확인은 서로 다른 단계에서 처리됩니다.

진단에는 자동 수집 공고의 짧은 인용문과 출처 파일·점수·자격 대조 결과를 포함합니다. 수동 입력·보완·판단 기록이 있는 공고는 개별 예시에서 제외하고, 전체 본문과 프로필·환경변수도 진단 파일에 넣지 않습니다. 구버전 자료에는 첨부 추출 문자 수가 기록되지 않았을 수 있습니다.

## 추천과 관련 후보

| 표시 | 의미 |
|---|---|
| 추천 | 연구 내용·자격·마감·핵심 자료 확인을 통과한 공고 |
| 관련 후보 | 연구 관련성은 있지만 자격이나 자료를 더 확인해야 하는 공고 |
| 검토 대기 | 자료 부족·처리 실패·적합도 기준 미달로 추가 검토가 필요한 공고 |
| 제목 미선별 | 제목에서 통신 관련 표현을 확인하지 못한 자료 |

기본 화면은 **추천·관련 후보**를 함께 보여줍니다. 관련 후보는 추천 건수에 포함하지 않습니다. 브리핑에는 추천 최대 20건과 관련 후보 최대 10건을 각각 표시하며, 이 숫자는 최종 표시 수입니다.

## 규칙 모드의 점수

점수는 연구 관련성이 높은 공고를 먼저 보여주기 위한 값입니다. 신청 자격과 마감은 별도로 확인합니다.

| 항목 | 배점 |
|---|---:|
| 구체적인 통신 연구 목표와 수행 내용 | 30 |
| 공고와 연구실 주제의 직접 관련성 | 1개 주제 24, 2개 32, 3개 이상 40 |
| 직접 관련성 없이 인접 기술만 연결 | 위 항목 대신 14, 추가 검토 필요 |
| 하나의 세부 과제 내용 확인 | 20 |
| 연구과제 모집 확인 | 10 |

같은 주제에 연결된 실적이 여러 개라면 공고와 실적 제목·제공 초록의 공통 기술 표현이 많은 실적을 우선합니다. 비교 범위는 등록된 프로필이며, 실제 인력·장비와 논문 전문은 따로 검토해야 합니다.

대학의 신청 역할이 명시된 문장을 찾고, 기업의 보증보험 면제·우대·가점은 해당 조건의 적용 범위를 확인합니다. 허용과 제한 문장이 충돌하거나 필수 기업 주관·컨소시엄 조건이 있으면 보류합니다. 법령 조문만 있는 자격도 추가 확인이 필요합니다. 상세 화면의 **자격 근거 대조**에서 문장과 출처를 비교할 수 있습니다.

공고문·RFP를 읽지 못하면 검토를 보류합니다. 매뉴얼·양식·참고 법령의 오류는 따로 기록합니다. 참고자료 폴더 안에 있어도 RFP는 핵심 문서로 처리합니다.

## 요청 설정과 공식 재게시 경로

기본 수집 방식은 직접 HTTP 요청입니다. `ACL_RESPECT_ROBOTS=1`을 설정하면 robots.txt 확인을 켤 수 있습니다. 목록과 첨부에 같은 데스크톱 브라우저 형식의 User-Agent를 사용하며 `ACL_USER_AGENT`로 변경할 수 있습니다. 실제 설정은 진단에 기록합니다.

사이트가 401/403/429, 로그인, CAPTCHA 화면을 반환하거나 동적 목록을 읽지 못하면 오류·확인 필요로 표시합니다. TLS 인증서 확인, 공개 주소 검사, 요청 간격과 제한된 오류 재시도를 적용합니다. 과거 robots 제한 기록은 새 요청 결과로 갱신됩니다.

선택한 기관에 공식 재게시 경로가 등록돼 있으면 일반 수집과 개별 확인에 자동으로 포함합니다. 공유 경로는 한 번만 확인합니다.

| 선택 기관 | 자동 포함 경로 |
|---|---|
| IITP·NRF·NTIS | IRIS·KOITA |
| ETRI | KOITA |
| 미래도전·신속시범 | 방위사업청 |
| KRIT PMS | DTiMS |

화면에서는 직접 선택한 경로와 자동 포함한 경로를 구분합니다. 원기관과 재게시 출처의 결과도 따로 기록합니다. 재게시 자료는 원문의 변경·마감 정보를 함께 대조하세요. 같은 방식이 CLI와 `daily_run.py`에도 적용됩니다. ChatGPT 예약 작업은 별도로 관리합니다.

## 직접 확보한 자료 가져오기

새 공고는 **브라우저 자료 가져오기**, 기존 공고는 상세 화면의 **직접 받은 자료로 보완**을 사용합니다. 복사한 본문, 저장 HTML, 내려받은 첨부를 입력할 수 있습니다.

본문을 입력하면 이전 본문을 교체하고, 파일만 추가하면 기존 본문에 덧붙입니다. 미확보 필수 자료를 모두 제공했을 때만 해당 체크박스를 선택하세요. 서로 다른 RFP는 별도 공고로 입력합니다.

파일명·해시·확보 시각·원 URL과 원문 버전을 보존합니다. 수동 보완 자료가 있으면 자동 수집 때 이를 유지하고, 공식 원문 변경을 발견하면 다시 대조하도록 보류합니다.

| 형식 | 처리 |
|---|---|
| TXT·MD·HTML | 텍스트 추출 |
| PDF | pypdf로 텍스트 추출. Windows는 `setup_optional_windows.bat`로 설치 가능 |
| HWP 5·HWPX·DOCX | 문서 텍스트 추출 |
| ZIP | 내부 지원 문서 추출. 여러 과제가 들어 있으면 분리 입력 권장 |
| 이미지·암호화 파일·구형 DOC·손상 문서 | 직접 확인·변환 필요 |

파일은 하나씩 임시 파일로 전송하며 용량·파일 수·PDF 쪽수·본문 길이에 고정 상한을 두지 않습니다. 실제 처리량은 메모리·디스크·파일 구조에 따라 달라집니다. 압축 해제 비율과 16단계 이상 중첩에 대한 보호를 적용합니다. GPT 전송 단계의 별도 입력 한도는 [GPT 설정](GPT_API.md)에 정리했습니다.

직접 제공한 파일은 수집 선별과 별도로 읽습니다. 추천할 때는 현재 마감·제목·상세 조건을 동일하게 확인합니다.

## 명령 모음

```bash
python run.py collect --source iris
python run.py reanalyze
python run.py brief --output briefing.md
python run.py backup --output acl-backup.sqlite3
python run.py diagnose --output source-diagnostics.json
python -m unittest discover -s tests -q
```

wheel 패키지가 필요하면 다음 명령으로 빌드합니다. 기본 실행에는 소스와 Python을 사용합니다.

```bash
python -m pip wheel . --no-deps -w dist
```

인증서 지원이 필요하면 `setup_network_windows.bat`를 실행하고 서버를 재시작하세요. 테스트한 환경과 남은 확인 항목은 [검증 기록](VALIDATION.md)에 정리했습니다.

참고: [robots.txt 표준](https://www.rfc-editor.org/rfc/rfc9309.html) · [User-Agent 설명](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/User-Agent)
