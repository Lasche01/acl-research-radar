# ACL Research Radar v0.7.1

기본은 API·로컬 AI 없는 규칙 모드입니다. v0.7.0부터 선택형 GPT API 심사를 제공합니다. Python 3.10 이상과 브라우저가 필요합니다. GPT 모드는 [별도 실행·설정 안내](GPT_API.md)를 참고하세요. 아래 점수 배점은 기본 규칙 모드에 해당합니다.

## 업데이트와 실행

1. 기존 실행 창에서 Ctrl+C로 서버를 종료합니다.
2. 새 ZIP을 별도 폴더에 압축 해제하고 `start_windows.bat`를 실행합니다.
3. 화면 하단과 진단의 버전이 **0.7.1**인지 확인합니다.
4. **공고 다시 분석 → 공고 수집**을 실행합니다. 기존에 확보한 RFP를 먼저 새 규칙으로 판정하고, 이후 필요한 상세·첨부를 새로 수집합니다.

기본 데이터 폴더 `~/ACLBriefingData`, 기존 원문·버전·피드백·경로 선택을 보존합니다. `ACL_DATA_DIR`를 따로 지정했다면 같은 값을 사용하세요. 새 정책에서 목록을 다시 확인하며, 기존 저장 본문에서 마감 경과가 확인된 주소는 재요청을 생략합니다. 구버전의 추천은 새 심사 전 검토 대기로 표시합니다. macOS/Linux는 `python3 run.py serve`입니다.

## 수집·선별 순서

1. **마감 우선 확인**: 목록의 접수기간·마감일·접수상태를 먼저 확인합니다. 마감 경과와 접수 시작 전 공고는 상세 요청을 생략합니다. 게시일·등록일·사업 기간을 접수 마감으로 쓰지 않습니다.
2. **제목에서 통신 후보 선별**: 통신·전파·주파수·무선·네트워크·파형·빔·채널·MIMO·CSI·AFDM 등의 표현으로 1차 후보를 가립니다. 제목이 불명확하면 ‘제목 미선별’ 보류로 기록하고 상세·첨부는 열지 않습니다. 명백한 타 산업·행정 문서는 제외합니다.
3. **기간이 불명확한 통신 후보**: 상세 HTML 본문에서 기간을 확인합니다. 여전히 불명확하면 ‘기간 미확인’으로 보류하고 첨부를 다운로드하지 않습니다. 첨부에만 마감이 있는 경우 직접 자료를 확보해 확인해야 합니다. 마감 당일 종료 시각이 없으면 자동 첨부 분석을 보류합니다.
4. **기간 내 후보의 상세·첨부 분석**: 공고문·RFP를 읽고 실제 연구 모집, 핵심 통신 요구, 연구실 실적 대응, 대학 자격, 세부 과제·마감 근거를 심사합니다. 본문의 마감 정보가 목록보다 우선합니다. 명백한 제출 서식은 필수 RFP와 구분합니다.
5. **추천 우선순위**: 제목의 단어 개수로 추천하지 않습니다. 상세 요구와 연구실의 논문·특허·사업 연결 및 필수 조건 통과를 기준으로 추천하고, 통과한 후보는 적합도 순으로 표시합니다. 점수는 규칙 정렬 지표이며 확률이 아닙니다.

마감이 확인된 주소는 목록 제목·접수정보가 그대로인 동안 재방문하지 않습니다. 목록에서 연장된 기간·상태 또는 변경된 제목이 보이면 다시 확인합니다. 목록에 드러나지 않는 원문 내부의 재개·변경은 자동 감지하지 못할 수 있습니다. 접수기간이 명확하지 않은 자료를 기한 내 공고라고 추측하지 않습니다.

기관별 목록 한 쪽과 해당 상세 대기 묶음을 처리한 뒤 다음 기관으로 순환합니다. 한 기관의 과거 목록 전체를 마칠 때까지 다른 기관을 기다리게 하지 않습니다. 페이지·공고 총량에 고정 제한을 두지는 않지만 마감/제목에서 제외된 공고의 상세와 첨부는 생략합니다. 실제 발견한 페이지 링크만 따라가며 중복 목록·미지원 동적 목록은 진단에 남깁니다. 진행 표시의 **수집 중지**로 멈추고 다음 실행에서 재개할 수 있습니다. 성공한 상세는 24시간 동안 반복 요청을 생략하고, 실패한 상세는 실행당 한 번 시도합니다.

수집 경로 화면에는 마감 제외·시작 전·제목 보류/제외·기간 미확인·상세 분석·기확인 건너뜀 건수를 표시합니다. 마감 제외 자료는 새 상세 공고로 저장하지 않습니다. 기존 저장 자료는 삭제하지 않습니다.

## 추천이 0건일 때

화면의 진행 단계에서 **제목 미선별 / 기간 확인 대기 / 상세 심사 기록**을 나눠 확인하세요. 제목에서 보류한 목록은 검토 대기에서 분리했으며 ‘제목 미선별’ 또는 ‘전체 수집 자료’에서 열 수 있습니다. 기존 저장 자료를 삭제한 것은 아닙니다.

v0.5.1은 본문 위의 표·항목에 있는 접수기간·신청 자격을 함께 읽고, 상세 링크가 없는 목록을 계속 넘기지 않습니다. 링크 추출 실패는 수집 성공으로 집계하지 않습니다. 이때 해당 기관의 실제 상세 주소 해석은 여전히 보강이 필요할 수 있습니다.

업데이트 후 **공고 다시 분석 → 공고 수집**을 실행하세요. 다시 분석만으로는 누락된 첨부가 새로 다운로드되지 않습니다. 계속 0건이면 수집 경로의 **수집 진단 내려받기**로 개별 공개 공고의 보류 항목·본문 문자 수·첨부 상태를 확인할 수 있습니다. 수동 입력·보완·판단 기록이 있는 자료는 개별 예시에서 제외합니다. 새 진단에는 공개 자동 수집 공고의 짧은 근거 인용·출처 문서·점수 내역을 포함합니다. 전체 본문·프로필·환경변수는 포함하지 않습니다. 이전 기록의 첨부 추출 문자 수는 미기록일 수 있습니다.

추천 조건을 충족하는 공고가 실제로 수집돼야 추천이 생깁니다. 통합공고의 여러 RFP·법령 참조 자격·첨부에만 있는 마감·이미지 내용은 추가 확인이 필요할 수 있으며 임의로 통과 처리하지 않습니다.

## 추천과 관련 후보의 구분

기본 화면의 **추천·관련 후보**는 조건을 모두 통과한 추천과 연구 관련성이 있으나 자격·자료 확인이 필요한 후보를 함께 보여 줍니다. 후보에는 검토 대기와 조건 확인 필요 표시가 남으며 추천 통과 수에 넣지 않습니다. 추천만/관련 후보만/검토 대기/제목 미선별 필터를 사용할 수 있습니다. 브리핑의 추천 최대 20건과 관련 후보 최대 10건은 별도이며 실제 수집·분석 범위 제한이 아닙니다.

연구 적합도 점수와 신청 가능 판정은 별개입니다. 점수는 아래 규칙에 따른 정렬 지표이며 확률이나 실제 과제 수행 능력 평가가 아닙니다.

| 항목 | 배점 |
|---|---:|
| 구체적인 통신 연구 목표·행위 | 30 |
| 실적·주제의 직접 대응 | 1개 주제 24, 2개 32, 3개 이상 40 |
| 직접 대응 없이 인접 기술 관계만 확인 | 위 항목 대신 14, 직접 연구실 대응은 미확인 유지 |
| 하나의 세부 연구 요구 확인 | 20 |
| 연구과제 모집 확인 | 10 |

동일 주제의 여러 실적 중에는 원문 요구와 제목·제공 초록의 공통 기술 표현이 있는 실적을 우선합니다. 활성 주제·기존 실적 연결을 임의로 추가하거나 바꾸지 않습니다. 전체 논문 의미를 이해하거나 현재 인력·장비 역량을 인증하는 AI는 아닙니다.

대학 신청 자격은 명시적 문장을 확인합니다. 기업의 보증보험 면제·우대·가점 조건을 대학 신청 불가로 대체하지 않습니다. 대학 허용과 제한 문장이 함께 있거나 필수 기업 주관·컨소시엄 조건이 있으면 적용 범위를 검토합니다. 법령 참조만 있으면 미확인으로 둡니다. 상세 화면의 **자격 근거 대조**에서 허용·제한·추가 조건과 출처 문서를 확인할 수 있습니다.

핵심 RFP·공고문과 매뉴얼·양식·참고 법령을 구분합니다. 알려진 부속 자료의 오류가 핵심 심사를 일괄 차단하지 않으며, 실제 RFP 실패·OCR 미판독과 정체가 불명확한 문서 실패는 계속 보류합니다. 참고 자료 폴더 안의 RFP는 필수로 처리합니다. 부속 문서의 예제 마감·자격 문구를 현재 공고의 근거로 쓰지 않습니다.

## 요청 방식과 공식 재게시

v0.6.0의 기본 모드는 직접 HTTP 요청입니다. 설정에 따라 robots 확인 모드를 사용할 수 있습니다. 목록과 첨부에 같은 일반 데스크톱 브라우저 형식의 User-Agent를 보냅니다. `ACL_USER_AGENT`로 문자열을 지정할 수 있습니다. 선택적으로 `ACL_RESPECT_ROBOTS=1`을 설정하면 robots 확인 모드를 켤 수 있습니다. 실제 모드와 User-Agent는 진단에 기록합니다.

User-Agent 변경은 사이트의 실제 401/403/429 응답·로그인·CAPTCHA·동적 목록을 해결했다는 뜻이 아닙니다. 해당 응답은 실패 또는 확인 필요로 표시합니다. TLS 인증서 검사, 공개 주소 검사, 요청 간격과 제한된 오류 재시도는 유지합니다. 구버전의 robots 제한 기록은 과거 결과이며, 새 요청 후 실제 결과로 갱신됩니다.

일반 공고 수집과 개별 확인에서 알려진 공식 재게시 경로를 체크 여부와 무관하게 자동 포함합니다. 여러 기관이 공유하는 경로는 한 번만 확인합니다.

| 선택 기관 | 자동 포함 경로 |
|---|---|
| IITP·NRF·NTIS | IRIS·KOITA |
| ETRI | KOITA |
| 미래도전·신속시범 | 방위사업청 |
| KRIT PMS | DTiMS |

화면은 직접 선택과 자동 포함을 구별합니다. 기존 체크 설정은 바꾸지 않습니다. 원기관과 실제 수집 출처의 결과를 따로 기록하며 재게시 자료의 완전성·최신성을 보장하지 않습니다. 이 동작은 CLI와 `daily_run.py`에도 적용됩니다. 기존 ChatGPT 예약 작업 자체를 변경한 것은 아닙니다.

## 직접 받은 자료와 큰 문서

새 자료는 **브라우저 자료 가져오기**, 기존 공고는 상세의 **직접 받은 자료로 보완**을 사용합니다. 복사한 본문·저장 HTML·내려받은 첨부를 넣을 수 있습니다. 파일은 하나씩 임시 파일로 전송하며 고정 용량·파일 수·PDF 쪽수·본문 길이 제한은 없습니다. 실제 처리량은 메모리·디스크·파일 구조에 의존합니다.

본문 입력은 이전 본문을 교체하고 파일만 추가하면 기존 본문에 보완합니다. 미확보 필수 자료를 모두 제공했을 때만 해당 체크박스를 선택하세요. 다른 RFP는 별도 공고로 입력합니다. 파일명·해시·확보 시각·원 URL과 기존 버전을 보존합니다. 자동 수집은 수동 보완을 덮어쓰지 않으며 공식 원문 변경을 발견하면 대조 전 보류합니다.

TXT/MD/HTML/PDF/HWP 5/HWPX/DOCX/ZIP을 지원합니다. PDF는 `setup_optional_windows.bat`로 pypdf를 설치하세요. HWPX/DOCX의 불필요한 이미지는 읽지 않습니다. 이미지 OCR, 암호화 파일, 구형 DOC와 손상 문서는 별도 확인이 필요합니다. 여러 과제의 ZIP은 분리해 입력하세요. 비정상적인 압축 해제 비율·16단계 이상 중첩 보호는 유지합니다. 수동으로 제공한 파일은 자동 수집의 선별 단계와 별도로 읽지만, 추천에는 현재 마감·제목·상세 조건을 적용합니다.

## 검증과 명령

[검증 기록](VALIDATION.md)과 [개발 사례](CASE_STUDY.md)를 참고하세요. 정답 라벨이 없어 실제 정밀도·재현율은 측정하지 않았습니다. Windows 네이티브 BAT, 모든 실제 기관 수집 성공률과 실제 수중 통신 RFP 원본의 재수집 완료는 별도 미검증입니다.

```text
python run.py collect --source iris
python run.py reanalyze
python run.py brief --output briefing.md
python run.py backup --output acl-backup.sqlite3
python run.py diagnose --output source-diagnostics.json
python -m unittest discover -s tests -q
```

이 저장소에는 공개 점검을 거친 소스·테스트를 포함합니다. 필요하면 `python -m pip wheel . --no-deps -w dist`로 wheel을 빌드할 수 있습니다. `run.py` 실행에는 wheel 설치가 필요 없습니다. Windows EXE는 아닙니다. 인증서 지원이 필요하면 `setup_network_windows.bat`를 실행한 뒤 서버를 재시작하세요.
