# 공개 전 점검

> [문서 안내](README.md) · 공개 자료 관리

2026-11-09 기준 공개 파일과 커밋 이력의 인증정보·개인정보를 점검했습니다. 소스·문서·예제는 v0.7.1을 기준으로 합니다.

## 공개한 자료

| 자료 | 위치·범위 |
|---|---|
| 프로그램 소스와 실행기 | `aclbrief/`와 프로젝트 실행기 |
| 기관 경로와 초기 연구 프로필 | `aclbrief/data/`의 공개 정보 |
| 가상 공고와 자동화 테스트 | `examples/`, `tests/` |
| 사용·개발 문서와 테스트 기록 | `docs/` |
| 실제 실행 화면 1장 | 2026-11-09 규칙 모드 공고 검토함 |
| 가상 데모 화면 2장 | v0.7.0 규칙 모드에서 촬영한 가상 공고 |

실행 DB·백업, 수집 진단 원본, 실제 공고 첨부, 개인 판단 기록, 비공개 연구 자료, 대화 로그, 채용 안내 이미지와 빌드 ZIP은 공개 대상에서 제외합니다. 파일 제외 규칙은 [.gitignore](../.gitignore)에 있습니다.

## 점검 내용

- API Key·토큰·개인 키 형식, 이메일·계정 식별 쿼리, 개인 로컬 경로를 검색하고 사용 목적을 확인했습니다.
- [.env.example](../.env.example)은 빈 설정 예시이며, 테스트의 Key 문자열은 가짜 값입니다.
- 초기 연구 프로필에서 계정 식별 쿼리가 있던 개별 URL을 제외했습니다.
- 실제 검토함 이미지에는 인증정보·개인 연락처·개인 판단 입력값이 보이지 않는지 확인했습니다. 담당자 이름·전화번호가 있는 상세 캡처는 게시하지 않았습니다.
- 가상 데모가 임시 DB를 사용하고 실제 실행 데이터를 포함하지 않는지 확인했습니다.
- 문서 링크와 이미지 경로를 점검하고, 실제 실행 기록·가상 예제·모의 API 테스트를 구분해 설명했습니다.

추가 공개 전에는 `git ls-files`로 파일 목록을 확인하고 새 파일과 커밋 내용을 점검합니다. 이미 커밋한 인증정보를 발견하면 Key 폐기·재발급과 Git 이력 정리를 함께 진행해야 합니다.
