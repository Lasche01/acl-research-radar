# 공개 전 점검

> [문서 안내](README.md) · 공개 자료 관리

이 문서는 공개 파일의 범위와 민감정보 점검 절차를 설명합니다. v0.7.1의 공개 소스·예제·이미지를 기준으로 2026-11-09에 점검했습니다.

## 공개 범위

| 포함한 자료 | 위치·설명 |
|---|---|
| Python·웹 UI·실행·설정 소스 | `aclbrief/`와 프로젝트 실행기 |
| 공개 기관 경로와 연구 주제·실적 | `aclbrief/data/`의 초기 데이터 |
| 가상 공고·자동화 테스트 | `examples/`, `tests/` |
| 테스트 결과와 개발 기록 | `docs/` |
| 데모 스크린샷 2장 | 규칙 모드로 촬영한 가상 공고. [재현 방법](SCREENSHOTS.md) |

다음 자료는 공개 대상에서 제외합니다.

- 실제 API Key·토큰·로그인 정보·개인 키·사용 환경 파일
- 실행 DB·백업·수집 진단 원본·실제 공고 첨부·개인 판단 기록
- 비공개 연구 자료·대화 로그·채용 안내 이미지
- 빌드 ZIP과 캐시

## 1. 공개 파일 목록 확인

```bash
git ls-files
```

소스·문서·테스트·가상 예제만 포함됐는지 확인합니다. 환경 파일과 실행 데이터의 제외 설정은 [.gitignore](../.gitignore)를 확인하세요.

## 2. 인증정보와 개인 데이터 확인

API·클라우드 Key, 토큰·개인 키 형식, 이메일·계정 식별 쿼리와 개인 로컬 경로를 검색하고 해당 항목의 용도를 대조합니다.

- [.env.example](../.env.example)은 빈 변수로 작성한 설정 예시입니다.
- 테스트 코드의 Key는 가짜 문자열입니다.
- 초기 연구 프로필에서 계정 식별 쿼리가 있던 개별 URL을 제외했습니다.
- 데모는 임시 DB와 가상 공고를 사용합니다.

이미 커밋한 민감정보를 발견하면 Key 폐기·재발급 등 해당 정보에 맞는 조치와 Git 이력 정리를 함께 진행해야 합니다.

## 3. 문서와 이미지 확인

문서 링크가 열리는지, 이미지가 해당 예제의 화면인지 확인합니다. 현재 README 이미지는 v0.7.0의 규칙 모드 데모이며, 코드 테스트 로그는 v0.7.1 실행 출력입니다.

**확인:** 테스트 결과·실제 실행 결과·추가 확인 항목은 [테스트 기록](VALIDATION.md)과 [개발 사례](CASE_STUDY.md)에서 각각 확인할 수 있습니다.
