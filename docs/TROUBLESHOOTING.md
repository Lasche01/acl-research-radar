# 문제 해결

> [문서 안내](README.md) · [사용 가이드](USAGE.md) · 문제 해결

이 문서는 실행·수집·추천·GPT 요청에서 발생하는 문제를 증상별로 설명합니다. 먼저 아래 표에서 증상을 찾고, 해당 절차를 진행하세요.

## 빠른 확인

| 증상 | 먼저 할 일 | 상세 절차 |
|---|---|---|
| 실행기가 종료되거나 대시보드가 열리지 않음 | Python 버전과 실행 창의 오류 확인 | [실행 문제](#실행-문제) |
| 포트를 열 수 없음 | 다른 포트로 실행 | [포트 충돌](#포트-충돌) |
| 설치·서버 창을 닫아도 되는지 불명확 | 설치 완료 창은 종료, 서버 창은 사용 중 유지 | [실행 창 관리](#실행-창-관리) |
| 추천이 0건 | 제목·기간·상세 검토 단계 확인 | [추천 0건](#추천-0건) |
| 기관 수집 실패 | 수집 경로의 상태·단계·이유 확인 | [수집 실패](#수집-실패) |
| 첨부·이미지를 읽지 못함 | 핵심 문서인지 확인 후 보완 | [자료 보완](#첨부와-이미지-보완) |
| GPT 요청 실패 | 공고별 오류와 API 설정 확인 | [GPT 요청 실패](#gpt-요청-실패) |
| 모드·모델 변경 후 추천이 보류됨 | 공고 다시 분석 실행 | [이전 결과 보류](#이전-결과가-보류될-때) |

## 실행 문제

1. 프로젝트 폴더에서 Python 버전을 확인합니다.

   ```bash
   python --version
   ```

2. Python 3.10 이상인지 확인하고 직접 실행합니다.

   ```bash
   python run.py serve
   ```

3. 실행 창의 주소를 브라우저에서 엽니다. 기본 주소는 `http://127.0.0.1:8765`입니다.
4. macOS/Linux에서 `python`을 찾지 못하면 `python3`를 사용합니다.

**확인:** 실행 창이 유지되고 대시보드에 v0.7.1이 표시돼야 합니다. 실패하면 창에 표시된 오류를 확인하세요.

### 포트 충돌

기존 서버 창을 종료하거나 다른 포트로 실행합니다.

```bash
python run.py serve --port 8766
```

이 경우 `http://127.0.0.1:8766`으로 접속합니다.

### 실행 창 관리

- `setup_optional_windows.bat`, `setup_network_windows.bat`: 설치가 완료되면 닫을 수 있습니다.
- `start_windows.bat`, `start_gpt_windows.bat`: 서버가 실행되는 창입니다. 대시보드를 사용하는 동안 열어 둡니다.
- 서버 종료: Ctrl+C. 데이터는 지정한 데이터 폴더에 남습니다.

## 추천 0건

1. 검토함의 **제목 미선별 / 기간 확인 대기 / 상세 심사 기록**을 확인합니다.
2. **제목 미선별** 또는 **전체 수집 자료**에서 제목 단계의 자료를 확인합니다.
3. **관련 후보**를 열어 연구 관련성은 있지만 자격·자료가 부족한 공고를 확인합니다.
4. 기존 원문을 다시 검토하려면 **공고 다시 분석**을 실행합니다.
5. 본문·첨부가 부족하면 **공고 수집** 또는 자료 보완을 진행합니다.

**확인:** 추가된 원문과 인용문이 상세 화면에 반영됐는지 확인하세요. 보류 이유가 남으면 그 조건을 원문에서 확인해야 합니다. 기간·자격을 확인하지 못한 공고는 추천으로 확정하지 않습니다.

## 수집 실패

**수집 경로**의 상태·단계·원인과 다음 조치를 확인합니다.

| 진단 | 확인할 내용 | 조치 |
|---|---|---|
| 상세 링크 추출 실패 | 목록은 열리지만 게시물 주소를 찾지 못함 | 공식 재게시 경로 확인 또는 직접 확보한 자료 입력 |
| TLS 인증서 오류 | 시스템 인증서 지원 여부 | `setup_network_windows.bat` 실행 후 서버 재시작 |
| 시간 초과·연결 종료 | 기관 사이트와 현재 네트워크 상태 | 실행을 종료·재개하고, 계속 실패하면 진단 확인 |
| robots 정책 제한 | 실제 요청 설정과 최근 진단 시각 | 설정을 [사용 가이드](USAGE.md#요청-설정)와 대조하고 공식 재게시 경로·직접 자료 확보 활용 |
| 401/403/429·로그인·CAPTCHA | 접근 권한·요청 제한·자동화 방지 화면 | 공식 접근 수단이나 브라우저에서 확보한 자료 사용 |
| 반복·동적 목록 | 현재 페이지 방식의 지원 여부 | 기관별 링크·페이지 해석 보강 필요 |

**수집 중지** 후 다시 실행하면 대기열에서 이어갑니다. 연결 실패나 링크 추출 실패는 신규 공고 0건으로 집계하지 않습니다.

### 진단 파일 내보내기

화면의 **수집 진단 내려받기** 또는 다음 명령을 사용합니다.

```bash
python run.py diagnose --output source-diagnostics.json
```

진단에는 공개 자동 수집 공고의 짧은 인용문·출처 파일·점수·보류 이유를 포함합니다. 수동 입력·보완·판단 기록이 있는 자료는 개별 예시에서 제외합니다. 전체 본문·프로필·환경변수도 진단에서 제외합니다. 구버전 자료에는 첨부 문자 수가 기록되지 않았을 수 있습니다.

## 첨부와 이미지 보완

1. 공고문·RFP인지 매뉴얼·서식인지 확인합니다.
2. PDF 텍스트 추출이 필요하면 `setup_optional_windows.bat`로 의존성을 설치합니다.
3. 이미지·암호화·손상 문서·구형 DOC는 내용을 직접 확인하거나 지원 형식으로 변환합니다.
4. 상세의 **직접 받은 자료로 보완**에서 본문·파일을 추가합니다.
5. 미확보 필수 자료를 모두 제공했을 때만 해당 체크박스를 선택합니다.

**확인:** 상세 화면의 문서 출처와 보류 이유를 다시 확인하세요. 선택 매뉴얼의 오류는 따로 기록하고, 핵심 RFP 오류는 자료가 보완될 때까지 보류합니다.

## GPT 요청 실패

| 상황 | 조치 |
|---|---|
| Key·모델 미설정 | GPT 실행기에서 입력하거나 환경변수 설정 |
| HTTP 401 | Key 확인 |
| HTTP 403 | 프로젝트·모델 권한 확인 |
| HTTP 429 | API 잔액·요청 한도 확인 |
| 답변 형식·인용문·그래프 확인 실패 | 공고 원문과 프로필을 확인하고 재분석 |
| 호출 횟수 한도 도달 | 다음 재분석에서 미처리 공고 이어서 처리 |
| 입력 길이 초과 | 세부 RFP나 프로필을 나눠 입력 |

자동으로 오류 요청을 재시도하지 않습니다. 설정을 고친 뒤 **공고 다시 분석**을 실행하세요. 화면의 **설정됨**과 실제 요청 성공은 공고별 결과에서 구분해 확인합니다.

[GPT 설정과 한도](GPT_API.md)

## 이전 결과가 보류될 때

원문·프로필·모델·검토 모드가 바뀌면 저장된 결과의 적용 조건을 다시 확인합니다. **공고 다시 분석**으로 현재 설정의 결과를 생성하세요. 재분석은 저장된 원문을 사용하므로 첨부가 누락됐다면 수집이나 자료 보완도 필요합니다.
