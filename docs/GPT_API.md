# GPT API 연결과 AX 처리 흐름

v0.7.0은 기본 규칙 모드와 **선택형 GPT API 심사 모드**를 제공합니다. GPT가 공고의 연구 요구·신청 조건과 연구실 실적의 대응을 해석하고, 프로그램이 원문 인용과 그래프 경로를 검증합니다. 사용자가 최종 신청 여부를 판단합니다.

실제 OpenAI Responses API 요청 코드를 연결한 구현입니다. 공개 검증에는 **모의 응답을 사용했습니다.** 실제 Key를 사용한 유료 호출·모델별 정확도·비용·속도는 아직 검증하지 않았습니다. 모의 결과를 실제 GPT 실행 성과로 표시하지 않습니다.

## 실행

Python 3.10 이상이 필요합니다. API 연결은 표준 라이브러리로 동작하며 별도 OpenAI SDK 설치가 필요하지 않습니다. PDF 읽기는 기존 선택 의존성을 사용합니다.

Windows는 `start_gpt_windows.bat`, 터미널은 다음 명령으로 실행합니다.

```bash
python start_gpt.py serve
```

환경변수에 모델 ID와 Key가 없으면 실행 창에서 입력받습니다. Key는 숨김 입력하며 파일·DB·브라우저로 저장하거나 보내지 않습니다. 해당 Python 프로세스 환경에만 유지합니다. 실행 후 **공고 다시 분석**을 누르면 기존 원문을 GPT로 심사합니다. 서버 시작과 화면 조회만으로는 호출하지 않습니다.

| 변수 | 의미 |
|---|---|
| `OPENAI_API_KEY` | 본인의 API Key. 채팅·소스·GitHub에 붙여 넣지 않습니다. |
| `ACL_OPENAI_MODEL` | 본인 프로젝트에서 사용할 수 있는 Responses API·Structured Outputs 지원 모델 ID. 기본 모델을 임의로 지정하지 않습니다. |
| `ACL_AI_MAX_CALLS` | 작업당 요청 상한. 기본 20회, 1~200회. 금액·토큰 상한은 아닙니다. |
| `ACL_DATA_DIR` | 선택 데이터 폴더. 시험 데이터를 분리하려면 지정합니다. |

환경변수를 설정한 경우의 명령입니다. `--reviewer`는 하위 명령 앞에 둡니다.

```bash
python -m aclbrief --reviewer openai serve
python -m aclbrief --reviewer openai reanalyze
python -m aclbrief --reviewer openai collect --source iris
```

기본 `run.py`, `start_windows.bat`, `daily_run.py`는 규칙 모드입니다. Key나 예전 `ACL_AI_PROVIDER` 변수가 남아 있어도 유료 모드가 자동으로 켜지지 않습니다. GPT 예약 실행에는 위 명시적 CLI 명령을 사용하세요.

[.env.example](../.env.example)은 변수 설명용이며 `.env` 자동 로딩 기능은 없습니다. 실제 Key를 파일에 작성할 필요가 없습니다. Key는 [OpenAI API 플랫폼](https://platform.openai.com/api-keys)에서 관리합니다. API 요금·모델 권한은 본인 프로젝트에서 확인하세요.

## 자동화와 검증

1. 마감·접수 상태를 확인한 다음 제목에서 통신 후보를 선별합니다. 기간 미확인·마감·제목 미선별 자료는 GPT를 호출하지 않습니다.
2. 공고문·RFP와 선택 매뉴얼·서식·참고 법령을 구분합니다. 핵심 자료 실패는 보류하고 선택 문서 실패는 별도로 기록합니다.
3. 기간 내 통신 후보의 공고문·RFP 텍스트와 현재 연구 프로필을 GPT에 전송합니다. 프로필에는 제공된 연구 주제·논문·특허·사업 메타데이터와 그래프 연결이 포함됩니다. 외부 전송이 가능한 자료인지 먼저 확인하세요.
4. GPT는 실제 연구 모집, 핵심 통신 요구, 연구실 대응, 대학 직접 참여 자격, 세부 요구를 `yes/no/unknown`과 인용으로 반환합니다. 기업 가점·보증 면제와 필수 자격, 담당부서 이름과 연구 목표를 구분하도록 지시합니다.
5. 프로그램은 JSON 구조, 인용의 실제 원문 포함, 활성 주제와 기존 실적의 그래프 경로, 날짜·점수 범위를 검사합니다. 선택 매뉴얼에서만 얻은 근거는 통과하지 못합니다.
6. 다섯 조건 모두 `yes`, 미래 마감 확인, 적합도 70점 이상일 때 추천합니다. 마감 당일은 종료 시각을 사람이 확인하도록 보류합니다. 연구 관련성은 있으나 자격 등이 미확인이면 관련 후보로 남길 수 있습니다.
7. 사용자가 인용·실적 연결·부족한 근거를 대조하고 최종 판단과 피드백을 기록합니다. 피드백이 자동으로 학습되지는 않습니다.

GPT 점수는 연구 적합도 판단이며 확률·수행 능력 인증이 아닙니다. 규칙 모드의 고정 배점과 같은 척도로 비교하지 않습니다. GPT 웹 검색·이미지 해석·누락 첨부 수집을 추가하는 기능은 아닙니다. 정확한 인용·경로가 있어도 의미 판단 오류는 남을 수 있습니다.

## 호출과 오류 처리

- 고정 주소 `https://api.openai.com/v1/responses`, strict JSON schema, `store: false`를 사용합니다. 응답 저장 옵션을 끄는 것이 서비스 전체의 데이터 보존 정책을 보장하는 것은 아닙니다.
- 동일 원문·프로필·모델·심사 개정의 검증 완료 결과를 재사용합니다. 모드·모델이 바뀌면 이전 추천을 새 방식의 결과로 표시하지 않습니다.
- 호출 상한에 도달하면 보류하고 다음 재분석에서 완료 건은 재사용하며 미처리 건을 이어갑니다. API 오류를 자동 재시도하지 않습니다.
- 401/403/429, 연결 실패, 거절·불완전 응답, JSON·인용·경로 검증 실패는 검토 대기로 남습니다. 오류를 규칙 추천으로 대체하지 않습니다. 오류 본문·헤더·예외 문자열을 DB에 저장하지 않습니다.
- API 입력은 공고 텍스트 100,000자·프로필 JSON 60,000자까지입니다. 초과하면 분리 입력을 요청하며 일부를 잘라 추천하지 않습니다. API 전송에만 적용하는 한도이며 기존 수집·보관·규칙 모드 제한이 아닙니다. 모델의 실제 문맥 한도에 따라 더 작은 입력도 실패할 수 있습니다.
- 화면의 ‘설정됨’은 Key·모델 값이 있다는 뜻이며 인증·요금·모델 사용 가능 여부나 호출 성공을 보증하지 않습니다. 성공 여부는 개별 공고의 검증 결과에서 확인합니다.

## Key 없이 재현

```bash
python examples/verify_gpt_workflow.py
python -m unittest discover -s tests -q
```

합성 공고와 미리 만든 모의 응답으로 서비스 연결→인용·경로 검증→추천/보류를 시험합니다. 네트워크는 차단하며 실제 Key·사용자 DB를 사용하지 않습니다. 통합 구조의 재현 증거이며 모델 성능 실측이 아닙니다.

구현: [API 심사](../aclbrief/screening.py), [서비스](../aclbrief/service.py), [전용 실행기](../start_gpt.py), [통합 시험](../tests/test_gpt_mode.py), [응답 계약 시험](../tests/test_screening.py).
