# 개발 사례: 스팸성 공고와 유효 후보 누락을 함께 줄이기

## 문제

연구과제 탐색을 자동화했지만 안전관리 심사 결과, 기관 메뉴, 타 산업 AI 구축 사업까지 결과에 섞였습니다. 필터를 엄격하게 바꾸자 추천이 0건이 되었고, 실제 관련 RFP를 확보해도 검토 대기나 제외로 남았습니다. 수집량 증가와 추천 품질 개선은 다른 문제였습니다.

## 사용자 판단을 구현 조건으로 바꾼 과정

| 관찰·사용자 판단 | 설계에 반영한 조건 | 코드·시험 |
|---|---|---|
| 마감된 공고까지 상세히 읽을 필요가 없음 | 목록에서 마감 우선 확인, 기간 내 후보만 첨부 분석 | `triage.py`, `test_v050.py` |
| 기관명·단순 배경의 통신 단어가 오탐을 만듦 | 기관 접두어와 연구 제목 구분, 연구 행위·주제 근거 확인 | `rule_evidence.py`, `test_v060.py` |
| 같은 연구 목표에 ‘본 공고의’를 붙이면 보류됨 | 공고 단어만으로 기술 문장 전체를 제거하지 않음 | `test_adding_this_announcement_does_not_erase_research_evidence` |
| 기업 보험 면제 조건이 대학 신청 불가로 해석됨 | 신청 대상 제한과 부가 혜택 문구를 구분 | `test_enterprise_only_guarantee_exemption_is_not_application_exclusion` |
| 매뉴얼 판독 실패가 공고 전체를 막음 | 핵심 RFP·공고문과 매뉴얼·서식·참고 법령 역할 구분 | `documents.py`, `DocumentRoleTests` |
| 연구 연결은 있으나 자격을 확정할 수 없음 | 연구 적합도와 자격 판정을 분리, 관련 후보로 보관 | `rules.py`, `test_missing_eligibility_does_not_reset_research_priority` |
| 논문 연도만으로 연결 실적을 선택하면 부정확함 | 기존 주제 연결 안에서 제목·제공 초록의 공통 기술 표현 우선 | `test_matching_evidence_text_is_preferred_over_publication_recency` |

각 시험 이름은 [test_v060.py](../tests/test_v060.py)에서 찾을 수 있습니다.

## 재현 가능한 결과

[합성 사례 실행](../examples/verify_evidence.py)은 외부 HTTP·사용자 DB 없이 같은 문장의 표현 변화, 대학 조건 누락, 기업 보험 면제 조건을 넣어 현재 판정을 출력합니다. 실제 공고의 신청 자격을 가정하는 테스트가 아닙니다.

과거 규칙에서 같은 연구 목표 앞에 ‘본 공고의’를 추가하면 점수가 0으로 바뀌던 사례를 개발 중 재현했습니다. v0.6.0 회귀 시험은 변경 전후 점수와 추천 판정이 같아야 한다고 검사합니다. 과거 버전 소스가 현재 브랜치에 실행되는 것은 아니므로, 이 기록을 실제 공고 전수 A/B 평가로 해석하지 않습니다.

## 운영 결과의 해석

사용자가 제공한 v0.6.0 실행 진단에서 수중 통신채널 관련 공고가 관련 후보 1건으로 분류되었습니다. 상태는 검토 대기, 연구 적합도는 74점, 확정 추천은 0건이었습니다. 이 값은 정답 라벨이 있는 평가의 정확도가 아니라 실제 실행에서의 분류 기록입니다.

진단의 근거 문장을 확인하니 가점 조건이 필수 기업 주관 조건으로 읽히고, 일부 담당자·배경 문구가 연구 근거로 잡히는 문제가 남아 있었습니다. ‘후보가 생겼다’와 ‘판정이 완전히 맞다’를 구분했습니다. 수집 진단을 통해 추출 단계와 판정 단계를 나누어 확인할 수 있게 한 것이 후속 검증의 기반입니다.

## v0.7.0: GPT 의미 심사와 근거 검증 연결

규칙만으로 문장 문맥을 구분하기 어려운 문제를 다루기 위해 선택형 GPT API 모드를 추가했습니다. 공고문·RFP와 연구 프로필을 보내 연구 요구·실적 대응·신청 자격의 구조화된 판정과 인용을 받습니다. 필수 자격과 가점·부가 혜택, 담당자 소개와 연구 목표를 구분하도록 지시합니다.

GPT 결과를 그대로 추천으로 사용하지 않습니다. 원문 인용·활성 주제·기존 실적 경로·날짜를 프로그램이 검사하고, 근거 오류나 API 실패는 보류합니다. 선택 문서는 근거 입력에서 분리합니다. [합성 모의 실행](../examples/verify_gpt_workflow.py)은 정상 인용의 통과, 만들어 낸 인용의 보류, 자격 미확인 후보의 보존을 재현합니다.

실제 API로 위 잔여 오류를 해결했다고 주장하지 않습니다. API 실행 경로와 실패 처리의 구현·모의 시험을 마쳤으며, 실문서와 모델 성능의 검증은 다음 과제입니다. [설계·실행·범위](GPT_API.md)를 참고하세요.

## 남은 과제

1. 가점·우대·기재 예시와 필수 신청 조건의 구분을 실제 문서 구조에서 보강.
2. 담당자·사업명·배경·향후 활용 가능성을 필수 연구 요구와 구분.
3. RFP 내용, 현재 공개 실적과 인접 기술 관계를 전문가 판단으로 대조.
4. 미지원 기관별 링크·페이지 이동 방식 보강과 실제 성공률 측정.
5. 관련/무관 정답 표본과 평가 분할을 확보해 정밀도·재현율 비교.

## 이력의 범위

공개 소스는 v0.6.0 스냅샷에 v0.7.0 선택형 API 구현을 추가한 내용입니다. 개발 중의 파일 교환·대화·개인 실행 DB를 과거 커밋으로 소급해 만든 이력이 아닙니다. 현재 재현 가능한 시험과 구현을 증빙으로 제공합니다.
