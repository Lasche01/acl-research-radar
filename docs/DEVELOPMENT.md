# 개발 과정과 AI 활용

연구실이 참여할 수 있는 통신 과제를 찾기 위해 개발한 프로그램입니다. 공고를 자동으로 모으는 것에서 시작해, 실제 연구 내용과 신청 조건을 확인하고 연구실 실적과 비교하는 기능을 추가했습니다.

## 직접 정한 기준과 검토한 내용

- 통신 분야이며 대학 연구실이 참여할 수 있는 공고를 대상으로 정했습니다.
- 마감을 먼저 확인하고, 제목에서 후보를 좁힌 뒤 상세 내용을 읽도록 처리 순서를 바꿨습니다.
- 연구 관련성과 신청 자격을 분리해, 자격이 불명확한 공고도 관련 후보로 확인할 수 있게 했습니다.
- 규칙 버전을 Windows에서 실행하며 오류 화면과 진단 파일을 확인했습니다.
- 안전관리 심사 결과, 다른 산업의 AI 사업, 연구실과 관련된 수중 통신 과제 등을 대조하며 오탐과 누락 원인을 검토했습니다.
- 문서 구분, 가점 문구 처리, 연구 실적 연결 방식의 수정 방향을 정했습니다.

## AI 코딩 도구 활용

Python 코드, 웹 화면, 수집·문서 추출 로직과 테스트 작성에 AI 코딩 도구를 활용했습니다. 실행 중 발견한 문제를 설명하고, 제안된 수정 내용을 실제 공고와 진단 결과에 비추어 검토하는 방식으로 개발했습니다.

예를 들어, 기업의 보증보험 면제 조건을 대학의 신청 제한으로 해석하는 문제가 있었습니다. 해당 문장을 필수 자격과 구분하도록 수정하고, 같은 유형의 문장을 넣은 테스트로 결과를 확인했습니다. 일부 가점 문구에서는 비슷한 오류가 남아 있어 추가 개선이 필요합니다.

[오류 사례와 수정 내용](CASE_STUDY.md)

## 프로그램에서 GPT를 사용하는 부분

v0.7.0부터 GPT API로 공고를 검토하는 모드를 추가했습니다. GPT는 공고문·RFP와 연구 프로필을 읽고, 연구 관련성과 신청 조건을 원문 인용과 함께 반환합니다. 프로그램은 인용문이 원문에 있는지, 선택한 실적과 연구 주제가 그래프에서 연결되는지 확인합니다. 최종 신청 여부는 사람이 원문을 검토해 결정합니다.

[GPT 호출과 답변 확인 과정](GPT_API.md)

## 현재 확인한 결과

자동화 테스트 252개를 통과했습니다. GPT API 연동은 모의 응답으로 테스트했으며, 실제 API 호출과 공고 추천 정확도 평가는 아직 진행하지 않았습니다. 기본 규칙 버전의 실제 실행 결과와 남은 오류는 [개발 사례](CASE_STUDY.md#실행-결과)에 정리했습니다.
